# Modules Options

## `modules`

Stackpanel modules that provide features and UI panels.

Modules are the unified way to extend stackpanel functionality:

Each module can define:

Modules can be:

| Property | Value |
|----------|-------|
| **Type** | `attribute set of (submodule)` |
| **Default** | `{ }` |

**Example:**

```nix
{
  postgres = {
    enable = true;
    meta = {
      name = "PostgreSQL";
      description = "PostgreSQL database server";
      icon = "database";
      category = "database";
    };
    source.type = "builtin";
    features = {
      services = true;
      healthchecks = true;
      packages = true;
    };
    healthcheckModule = "postgres";
  };

  my-custom-module = {
    enable = true;
    meta = {
      name = "My Custom Module";
      description = "Does something useful";
      category = "development";
    };
    source = {
      type = "flake-input";
      flakeInput = "my-module";
    };
  };
}
```

## `modules.<name>.configSchema`

JSON Schema string for generating configuration forms in the UI. The schema should describe the module's configurable options.

| Property | Value |
|----------|-------|
| **Type** | `null or string` |
| **Default** | `null` |

**Example:**

```nix
''
  {
    "type": "object",
    "properties": {
      "port": { "type": "integer", "default": 5432 },
      "version": { "type": "string", "enum": ["15", "16"], "default": "16" }
    }
  }
''
```

## `modules.<name>.actions`

An attribute set keyed by action ID. An action declares an executable `script`, display metadata, optional `confirm`, a JSON object `argsSchema`, `outputMode` (`stream` or `json`), and collections to refresh on success. Reference action IDs from panels; panel controls never contain shell commands.

## `modules.<name>.enablePath` and `configPath`

Paths relative to `stackpanel`. The defaults are `modules.<name>.enable` and `modules.<name>.settings`. The agent writes these options in the evaluated project configuration. `readme` supplies Markdown documentation for the installed module.

## Module-owned panels

No panel is required for the standard module UI. `mkModule.ui.widgets.<id>.<kind>` adds a [Nix-authored layout](/docs/extensions/writing-extensions#author-a-panel-in-nix). Additional panels live under [`stackpanel.panels`](./panels), not inside the module descriptor; `mkModule` sets their owner.
