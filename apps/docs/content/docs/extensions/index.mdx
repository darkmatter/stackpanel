A Stackpanel extension is a **Nix module**. A local module, a bundled module, and a flake from a registry all use the same options and `lib.stackpanel` helpers. A module can add an app runtime, generate a file, provide a service, or put a panel in Studio without changes to Stackpanel's Go binary or web app.

There are three separate decisions:

1. **Install** makes a module's definitions available. A remote module is a flake input pinned by your project's `flake.lock`.
2. **Enable** turns on the module's behavior. Studio and the CLI patch the Nix configuration that the project actually evaluates. An installed but disabled module is still visible in **Studio → Modules**.
3. **Apply** materializes generated files and rebuilds the shell when necessary. Evaluating a preview does neither.

The registry is a **catalog**, not a Nix package manager. It helps people find the input and a version. Nix does not consult the catalog, the network API, or the agent during module evaluation.

Studio generates a module's settings, action controls, outputs, and documentation from its declaration. For a custom layout, [declare widgets in Nix](./writing-extensions#author-a-panel-in-nix); the module starter supplies editor completion and hover from its locked SDK. Standalone HTML panels can import the same Web Components without React.
