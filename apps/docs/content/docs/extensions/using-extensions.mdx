---
title: Using modules
description: Install, preview, enable, update, and remove a module in a project.
icon: puzzle
---

Run the CLI in the consumer project. In Studio, select that project before opening **Modules**. Search is a catalog operation; **List all** also shows the local and bundled modules that this project can enable.

```sh
stack module search playwright
stack module install playwright
stack module list --all
stack module info playwright
```

In Studio, open **Explore Modules**, choose a registry entry, and click **Install**. This adds and locks the flake input; it does not enable the module or mount its panels. Review the adoption and file plan, then click **Enable** to see the module’s UI. Module-detail panels appear in **Installed → Configure module → Overview**; a sidebar panel such as Fly appears under its declared navigation section. Inspect `flake.nix`, `flake.lock`, and `.stack/config.nix` in your diff. Rebuild the devshell when Studio prompts.

The CLI asks about each optional offer, previews the effects of your answers, and asks for final approval before enabling. Press Enter at an offer to leave it unanswered. Cancelling the final preview leaves the locked input installed but does not save answers, enable the module, or materialize files.

For automation, `--yes` on `install` or `enable` approves enabling and reconciling **without adopting unspecified offers**. Add `--adopt-defaults` to accept the declared defaults, `--with <offer>` to accept an offer, `--without <offer>` to record a decline, or `--addon <offer>=<value>` for a boolean, choice value, or comma-separated selection. Offer decisions are recorded at the revision you reviewed.

```sh
stack module enable playwright
stack module disable playwright
stack module update playwright
stack module uninstall playwright
```

Disabling leaves the input installed. Uninstalling removes the input and its explicit module import, if it had one. Neither is permission to delete files you own. Check the reconciliation plan for generated files. To install a catalog version other than the latest, select it in Studio or use `stack module install <id>@<version>`.

### Where settings live

`.stack/config.nix` is the source of truth; entries in this file are relative to `stackpanel`. For a module using the default paths:

```nix
{
  modules.playwright.enable = true;
}
```

The module can declare a different `enablePath` or `configPath` when it owns another option namespace. Use the module’s README and configuration form rather than guessing a path from its name. Per-app options belong in `apps.<app>`.

### Running an action

`stack module info <id>` lists the available actions. Run one with `stack module run <id> <action>` or use its button in Studio. A module defines the accepted arguments, the command, and whether the result is a stream of output or JSON. Panels do not submit arbitrary shell commands.

### Trust

Read the source before adding a new input. A pinned module is reproducible, **not** sandboxed project code: it can contribute build steps and commands that you may later execute as your user. The iframe sandbox limits a module's *frontend*; it does not make an untrusted flake, action, or daemon safe to adopt.
