# Stackpanel module contract

A module publishes `stackpanelModules.default` from a flake, or lives in the consumer's tracked `.stack/modules/` or `.stack/nix/` directory. The consumer supplies `lib.stackpanel`. Built-in modules use the same registry, actions, and Studio renderer as external modules.

Use `lib.stackpanel.mkModule` for metadata, typed settings, activation, per-app options, packages, actions, and panels. The root flake also exports the constructors, `spField`, runtime JSON Schema generation, `panels`, `ports`, and `validateModule` under `lib` for use outside an active consumer evaluation. `stackpanelModuleMeta` describes flake-level overlays and flake-parts modules. Those imports cannot depend on per-project evaluated options.

- **Discovery:** lock direct flake inputs or use tracked local files. Enablement and settings live in `.stack/config.nix`, not in a second agent data file.
- **Registration:** `stackpanel.modules.<id>` is the module descriptor. Use `stackpanel.panels.<id>.module` for panel ownership. Add explicit ownership to files, scripts, tasks, and services. A module can appear in the catalog or project without being enabled.
- **Operations:** `stackpanel.modules.<id>.actions` names executables, argument schemas, output modes and confirmation prompts. Studio never interpolates an input into a shell command. A module daemon is proxied only with explicit ownership, loopback port, and opt-in.
- **UI:** no frontend is required. `mkModule.ui.widgets.<id>.<kind>` compiles to the shared json-render format. Use `panels.<id>.spec.widgets` with `slot` for other surfaces, or pass a raw JSON document. The `#module` template pins the editor-only SDK in `dev/flake.lock` so nixd can offer widget properties and hover docs. The catalog and sandboxed HTML panels share Web Components from `@stackpanel/extension-sdk/elements`. Module-authored JavaScript never runs on the Studio page; only the host may authorize a frame's service request or module command.
- **Development:** `stack module dev` opens a scratch consumer. `stack module link` replaces a project input on one machine with `--override-input`, leaving `flake.lock` intact. `stack module eject` promotes a project-local module into its own flake.
